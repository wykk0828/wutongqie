用户输入：`$ARGUMENTS`

`/change` 的默认动作是**准备切换会话**：把当前对话整理成一份交接文档，并给出一段可直接粘贴到新会话的开场提示。

按参数分流（工具在宿主里通常显示为 `mcp__plugin_wutongqie_wutongqie__<工具名>`，以实际可用工具为准）：

- 参数为空，或"交接"、"换会话"、"新会话"、"准备切换" → 调 `prepare_switch`，**不要传 sessionId**：它会自动选中当前/最近的主会话，并且**立即返回**，不需要等待模型。
  - 返回 `status: "cached"`：内容没有变化，直接复用了已有的最终交接。告诉用户"已经是最新交接，无需重新生成"，把路径、开场提示和摘要要点给出即可，后台不会再跑任务。
  - 返回 `status: "queued"` 或 `"running"`（`background: true`）：先拿到一份可立即复制的交接草稿（`draft`），后台继续完善同一份 `TOTAL.md`。把草稿路径、可复制的开场提示（`handoverText`）和摘要要点（当前进展、未完成事项、用户偏好与硬约束）讲给用户，并说明"可以先复制给新会话，不用等；后台完成后下一轮对话会自动播报最终版"。不要只丢路径，也不要让用户等待或反复问进度。
- "面板"、"panel"、"ui" → 调 `open_panel`（cwd/sessionId 可选，默认当前会话），把返回的 `http://127.0.0.1:<port>/` 链接给用户，并说明面板里能做什么。
- "历史"、"列表"、"归档"、"list" → 调 `list_sessions` 和 `list_chunks`，整理成表格给用户；要看某段细节再调 `read_chunk`。
- "状态"、"status"、"排障" → 调 `archive_status`，原样展示关键信息。
- 参数无法识别 → 简短列出上面几种用法，并问用户是否现在就准备交接。

说明：

- 归档本身是自动的（每次上下文压缩后由后台完成），这个命令只是在用户想用结果时把它取出来。
- 草稿是无模型的机械拼接，边界渲染不改归档状态；最终交接由后台 worker 用模型归并并覆盖同一路径的 `TOTAL.md`，所以现在复制路径、稍后打开的仍是同一份文档。
- 若返回 `warnings`（例如某次模型调用失败），如实说明哪部分可能不完整。
- `build_total_summary` 是旧版兼容工具，与 `prepare_switch` 同样的立即返回行为、参数同样全部可选（`sessionId` 可不传），仍可用但不再是首选；新流程统一走 `prepare_switch`。
