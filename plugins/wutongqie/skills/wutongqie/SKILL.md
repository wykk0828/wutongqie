# 无痛切

命令入口为 `/change`，无参数时准备切换会话；`/change 面板`、`/change 历史`、`/change 状态` 分别打开面板、查看历史和排障。

让「换会话」不再丢上下文：被压缩吞掉的对话平时自动归档，要换会话时一键生成交接文档。

## 主流程：用户要换会话 / 要交接

用户说「我要换会话」「准备开新对话」「生成交接文档」「保存这次对话」「把这次聊的总结一下」时：

1. 调 `prepare_switch`（宿主里通常显示为 `mcp__plugin_wutongqie_wutongqie__prepare_switch`），
   **不要传 sessionId**——它会自动选中当前或最近使用的主会话，不需要先查会话列表。
   只有用户明确点名"另一个会话"时，才考虑传 `cwd` / `sessionId`。
2. 它**立即返回**，不要告诉用户"要等几分钟"，也不要让他干等：
   - `status: "cached"`：内容没有变化，直接复用了已有的最终交接，把这份给用户即可（后台不会再跑任务）；
   - `status: "queued"` / `"running"`（`background: true`）：已经拿到一份可立即复制的机械草稿（`draft`），后台正在完善同一份 `TOTAL.md`。
3. 把这三样给用户（草稿和最终版都在同一个 `TOTAL.md` 路径上）：
   - **交接文档的绝对路径**（磁盘上的 `TOTAL.md` 就是这份文档，界面上统一叫"交接文档"）；
   - **一段可直接复制到新会话的开场提示**（工具返回的 `handoverText`）；
   - **摘要要点**：当前进展（overview）、未完成事项（conclusions）、用户的偏好与硬约束（constraints）。
     不要只丢路径，要把要点讲出来。
4. 明确告诉用户：现在就可以把开场提示复制到新会话，**不用等**；后台完成后会在**下一轮对话**自动播报最终版，同一路径的 `TOTAL.md` 会被替换为精炼版。
5. 如果工具返回了 `warnings`（比如某次模型调用失败），如实告诉用户哪部分可能不完整。

## 打开面板

用户说「打开面板看看」时调 `open_panel`（可选传 `cwd` / `sessionId`，默认当前会话），
把返回的 `http://127.0.0.1:<port>/` 链接给用户。
面板首页主按钮就是「准备切换会话」，生成完成后可以在页面上直接复制开场提示。

## 找回之前聊的内容

用户说「我们前面聊到哪了 / 之前说了什么」时：

1. 调 `list_sessions` 看工作区里有哪些会话（一般只有一个主会话）。
2. 调 `list_chunks` 看有哪些归档段；用户要细节再调 `read_chunk`，
   `file` 传 `TOTAL.md` 读交接文档全文，传 `LIVE.md` 读尚未被压缩的最新内容。
3. 如果什么都没有归档，说明还没发生上下文压缩，属于正常情况，不用调 `archive_now` 硬补；
   用户要交接就直接走主流程（`prepare_switch` 只包含当前内容也能生成交接文档）。

## 排障

调 `archive_status` 看后台任务、最近日志和可用的模型供应商。常见情况：

- **没归档** → 钩子还没跑，或后台任务还在跑（`archive_status` 里能看到）。
- **摘要失败** → ZCode 里配置的供应商都调不通，在面板「高级设置」里换一个。
- **某个供应商不可用** → 本插件只支持 `openai-chat-completions` 类型，
  `openai-responses` 类型（如 Grok）会显示为不可用。

## 兼容旧工具

`build_total_summary`（旧名）仍在，与 `prepare_switch` 是同一套立即返回行为，参数也完全可选
（`sessionId` 可不传，自动解析当前/最近的主会话）；它**不是首选**，只在 `prepare_switch`
不可用时作为兜底。

## 注意

- 归档**完全自动**，用户平时不需要做任何事。不要主动提醒"我帮你归档了"，
  除非插件在对话里已经播报过（默认静默）。
- 不要让用户干等或反复问进度：立即返回的草稿已经可用，最终版会在下一轮对话播报；
  不要编造剩余时间。
- 摘要会把对话内容发送给 ZCode 里配置的模型供应商，并产生真实 token 消耗；
  用户问起时如实说明。归档目录默认是 `<工作区>/.无痛切/`，不要提交到 git。
- 对普通用户只说「交接文档」「准备切换会话」；sessionId、LIVE、分段文件等内部术语
  只在排障或用户主动问起时出现。
- 当前阶段只支持 ZCode；架构上已为其他 agent（如 Codex）留了适配层，接入后再说。
